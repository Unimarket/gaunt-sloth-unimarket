# v2.1.0

## New Features

- **`commandEnv`** controls what a command spawned by the shell tool or a custom tool inherits.
  Set `commandEnv.scrubCredentials` to `true` to remove every variable whose name ends in `KEY`,
  `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD` or `CREDENTIALS`, and list the ones a command may keep in
  `commandEnv.passthrough`. See
  [A spawned command's environment](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.1.0/docs/configuration/tools.md#a-spawned-commands-environment-commandenv).

## Potentially Breaking Changes

- **Security-relevant: spawned commands now keep your credentials by default.** The shell tool and
  custom tools used to remove API keys and tokens from a command's environment; they now inherit
  Gaunt Sloth's environment unchanged, so a command that runs `gth` itself or calls a model API finds
  its keys. A command that prints its environment puts those keys into the tool result, which is sent
  to the model provider and saved in session history. To keep isolation, set
  `commandEnv.scrubCredentials` to `true`. With scrubbing on, `GITHUB_TOKEN` and `GH_TOKEN` are no
  longer exempt: add them to `commandEnv.passthrough` if a command needs them.
- For code importing `@gaunt-sloth/agent/tools/shell/env.js` directly: `buildScrubbedEnv` is
  replaced by `buildCommandEnv(policy, source)`, which returns `{ env, removed }` and scrubs only
  when the policy says so; `CREDENTIAL_ALLOWLIST` is removed; and `shouldScrubEnvVar` now takes a
  passthrough list as its second argument, with `isCredentialEnvVar` for the bare name test.
