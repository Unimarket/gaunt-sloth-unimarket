# v2.0.1

- `gth ask --resume <id> "…"` and `gth exec --resume <id> -m "…"` run one more turn in a recorded
  conversation, from its saved state — the tool results the earlier run gathered included. Any
  `ask`, `exec`, `chat` or `code` conversation can be continued by any of them, and
  `gth history resume <id> "…"` continues an `ask` or `exec` one. A single-shot resume does not
  restore approvals granted in an interactive session. See
  [Resuming a conversation](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/COMMANDS.md#resuming-a-conversation).
- A recorded `ask` or `exec` run now ends with the command that continues it, on stderr. Turn it off
  or add detail with
  [`output.resumeHint`](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/configuration/output.md#resume-hint-outputresumehint).
- **Recorded `ask` and `exec` runs now keep their saved state on disk**, which is what makes them
  resumable. Each saved step stores the whole conversation so far, so the store grows quickly on a
  long run: one long `exec` run was measured at 1.6 GB. Nothing removes a recorded run's state
  automatically. Reclaim the space with `gth history prune`; see
  [What the store keeps, and what reclaims it](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/COMMANDS.md#what-the-store-keeps-and-what-reclaims-it).
- **The history store is now a directory, with one SQLite file per conversation thread** and a
  small index for listing and search, instead of one file holding everything. The path does not
  change: `~/.gsloth/history.db`, or your `history.dbPath`, is now that directory. A store written
  by 2.0.0 is split into the new layout the first time any command opens it, once and without
  asking; on a large store this can take a few seconds. `gth history prune` now deletes whole
  thread files, deleting one file loses only what it held, and the new `gth history rebuild`
  rebuilds the index from the files. See
  [history](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/COMMANDS.md#history).
  2.0.0 cannot read the directory, and records no history while it is there, so move it aside
  before going back to 2.0.0.
- `gth history list`, `search`, `show`, `prune` and `gth insights` now open the store your config's
  `history.dbPath` names when you do not pass `--db`. They used to read the default store, so a
  configured store looked empty to them.
- `gth history resume` now exits with status 1 when it refuses a conversation, where it exited 0.
  Cells of a `batch`, `eval` or `workflow` run are marked as such in `gth history list` and are not
  resumable.
- `run_shell_command` takes an optional `cwd`, so the agent can run a command in a subdirectory
  without `cd … &&`. A `cwd` outside the project always asks for approval, at every approval mode
  except `bypass`, and `approvals.allow` entries do not apply there.
- When a command with a `cwd` outside the project stops a run that has no one to approve it, the
  message now says so. It names the working directory and the project directory and offers two ways
  forward: run it in a session where a person can confirm it, or use `bypass`. It no longer suggests
  an `approvals.allow` entry, which could not have helped.
- A Gemini API per-minute quota error that names a short wait (up to 90 seconds) no longer ends the
  run. Gaunt Sloth says it is waiting, waits the longer of the two waits the provider names, and
  carries on from where the turn stopped, at most twice per turn. A per-day quota, or a longer wait,
  ends the run as before.
- A failed write to the history store no longer ends the tool turn it happened in. The session
  carries on with its state held in memory and reports the failure once.
- Two broken links in the API reference now point at the functions they describe: the
  `resolveGrepFileSet` page links to `getDefaultTools`, and the `DEFAULT_CONFIG` pages link to the
  `github` content source's `get`.
