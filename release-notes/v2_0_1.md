# v2.0.1

- `gth ask --resume <id> "…"` and `gth exec --resume <id> -m "…"` run one more turn in a recorded
  conversation, from its saved state — the tool results the earlier run gathered included. Any
  `ask`, `exec`, `chat` or `code` conversation can be continued by any of them, and
  `gth history resume <id> "…"` continues an `ask` or `exec` one. A single-shot resume does not
  restore approvals granted in an interactive session. See
  [Resuming a conversation](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/COMMANDS.md#resuming-a-conversation).
- A recorded `ask` or `exec` run now ends with the command that continues it, on stderr. Turn it off
  or add detail with
  [`output.resumeHint`](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.1/docs/configuration/output.md#resume-hint-outputresumehint).
- `gth history resume` now exits with status 1 when it refuses a conversation, where it exited 0.
  Cells of a `batch`, `eval` or `workflow` run are marked as such in `gth history list` and are not
  resumable.
- Two broken links in the API reference now point at the functions they describe: the
  `resolveGrepFileSet` page links to `getDefaultTools`, and the `DEFAULT_CONFIG` pages link to the
  `github` content source's `get`.
